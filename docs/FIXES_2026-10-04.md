# Fixes to the Known Limitations

**Date:** October 4, 2026
**Covers:** the 32 limitations listed in [LIMITATIONS.md](LIMITATIONS.md) as of that date.

## Summary

| | Count | Limitation numbers |
|---|---|---|
| Fixed | 20 | 8–16, 18, 19, 21–27, 29, 31 |
| Partly fixed | 4 | 7, 17, 20, 32 |
| Not fixed | 8 | 1–6, 28, 30 |

The fixes are about access control, accounts, record handling and configuration. The limitations that remain are about what the OCR can read and about setting up a production server; the reasons are in [section 3](#3-not-fixed-and-why).

Checked by 26 automated tests, which all pass, and a successful frontend build. The screens themselves were **not** clicked through in a browser; see [section 6](#6-how-the-fixes-were-checked).

## 1. What was fixed

Each row shows how the system behaved before and how it behaves now. The number is the limitation's number in LIMITATIONS.md.

### Who can see what

| # | Before | Now |
|---|---|---|
| 10 | A teacher could open any record if they knew its ID. | A teacher can open only records of their own class. Others return "You can only view records of your assigned class." |
| 11 | Grade Analytics and Scan History showed the whole school to every teacher. | Teachers see analytics and scans for their own class only. |
| 12 | A teacher with no class assigned could see every record. | A teacher with no class assigned sees nothing, and is told: "Your account has no class assigned yet. Ask the OIC to assign your grade and section." |
| 13 | Everyone saw the same menu. Teachers saw pages and Delete buttons that only gave errors. | The menu shows only the pages your role can use. Teachers no longer see User Management, Audit Log, or Delete buttons. Admin Staff see the user list without the add, edit and delete controls. |
| 14 | Scanned forms could be fetched from `/media/scans/…` without logging in. | That address is removed. Scans can only be downloaded through the app, which checks who is asking. |

### Signing in and passwords

| # | Before | Now |
|---|---|---|
| 15 | Refreshing the page signed you out. | You stay signed in after a refresh. |
| 16 | There was no way to change a password in the app. | Every user has a **Change password** button at the top right. The OIC can also set a new password for any user from **Edit** in User Management. |
| 18 | Editing a user could change only the role and status. | The OIC can also change a user's name, assigned grade and section, and password. |

### Records

| # | Before | Now |
|---|---|---|
| 19 | A saved record could not be corrected. It had to be deleted and uploaded again. | OIC and Admin Staff have an **Edit record** button on the Record Detail page. They can correct the pupil details and any grade. The general average and remarks are recalculated on save. |
| 21 | Uploads that were started but never saved stayed on the server forever. | A clean-up command removes them (see [section 4](#4-new-maintenance-commands)). |
| 22 | Deleting a record left the pupil's scanned form on the server. | Deleting a record also deletes its scan and the image file. |
| 23 | Old records kept remarks worked out with old rules. | A command recalculates the average and remarks of every record (see [section 4](#4-new-maintenance-commands)). |
| 24 | Typing `(` or `[` in Search could cause a server error. | Search treats what you type as plain text. |
| 25 | Times were sent without a time zone, which makes a browser show them eight hours behind Philippine time. | Times are marked as UTC, so the browser shows them in the computer's local time. |
| 26 | The Dashboard's "Pending validation" number did not count unfinished uploads. | It is renamed **Unfinished uploads** and counts uploads that were read but never saved. |

### Choices in dropdown lists

| # | Before | Now |
|---|---|---|
| 8 | School years stopped at 2024-2025 and started at 2021-2022. | The upload form lists every school year from 1990-1991 to the current one, and selects the current one by default. |
| 9 | The section filter and the teacher's assigned section used a fixed list of five sections. Capital letters had to match exactly. | The filters list the sections that saved records actually use. A teacher's section is typed in, with suggestions. Capital letters no longer matter: "sampaguita" matches "Sampaguita". |

### Server settings

| # | Before | Now |
|---|---|---|
| 27 | Debug mode was on unless switched off, any host name was accepted, and a built-in secret key was used if none was set. | Debug mode is off unless `.env` switches it on. With debug off, the server refuses to start without a real `SECRET_KEY`. Accepted host names are set with `ALLOWED_HOSTS` and default to this computer only. |
| 29 | Only a frontend on `localhost:3000` could talk to the server, and changing that meant editing code. | The allowed addresses are set with `CORS_ALLOWED_ORIGINS` in `.env`. |
| 31 | `.env.example` and the built-in default named two different databases (`ocris` and `ocris_bcs`). | Both now say `ocris_bcs`. Existing `.env` files are not changed. |

## 3. Not fixed, and why

| # | Limitation | Why it was left |
|---|---|---|
| 1 | Only JPG and PNG, one image per upload | PDF and multi-page support needs a new library and a decision on how several pages become one record. |
| 2 | Fixed column order and a fixed list of nine subjects | Changing this safely needs real forms with other layouts to test against. |
| 3 | Handwritten grades are mostly flagged | A limit of the OCR engine. Flagging them for a person to check is the intended safe behaviour. |
| 4 | OCR takes about 17 seconds and blocks the request | Needs a background job system, which is new infrastructure. |
| 5 | A multi-year Form 137-A is saved as one record | Splitting it into one record per school year changes how records are structured. This needs a decision from the school on how they want such forms stored. |
| 6 | The typed pupil details are trusted over the scanned ones | Kept on purpose. OCR misreads names more often than people mistype them, and the mismatch warning already covers this. |
| 28 | The server runs on Django's development server | A deployment task, not a code change. It depends on where the system will be hosted. |
| 30 | MongoDB has no password by default | Set up on the MongoDB server itself. OCRIS already accepts a username and password in `MONGO_URI`. |

Still true as well: OCR accuracy has only been measured on one mockup form, and no test with real scans or with school staff has been recorded.

## 4. New maintenance commands

Run these in the `backend` folder. Add `--dry-run` to the first two to see what would change without changing anything.

| Command | What it does |
|---|---|
| `python manage.py cleanup_scans` | Deletes uploads that were never saved and are more than 7 days old, with their image files. Use `--days 30` to change the age. |
| `python manage.py recompute_remarks` | Recalculates the general average and remarks of every record using the current rules. Only records that would change are written. |
| `python manage.py backup` | Writes `backups/ocris-backup-<date>-<time>.zip` containing the accounts database, the MongoDB data and the scanned images. Use `--out <folder>` to choose where. |
| `python manage.py test` | Runs the automated tests. MongoDB must be running. The tests use their own temporary database and do not touch real data. |

On October 4, 2026 the first two were dry-run against the existing data: no records needed recalculating and there were no old unfinished uploads.

## 5. What you need to know after updating

These are changes in behaviour that could surprise someone used to the old version.

1. **Check `backend/.env`.** For development it must contain `DEBUG=True`. Without it the server now runs with debug off and will not start unless `SECRET_KEY` is a real value (not `change-me`).
2. **Opening the app from another computer** needs that address added to `ALLOWED_HOSTS` and `CORS_ALLOWED_ORIGINS` in `backend/.env`.
3. **Every teacher needs a grade and section.** A teacher account without them now sees no records. The User Management list shows "No class assigned" for these accounts; fix them with **Edit**.
4. **Deleting a record is more final.** The scanned form is deleted with it.
5. **Users are signed out after 12 hours** and sign in again.
6. **Setting a user's password from User Management signs that user out** on every device.
7. **The last active OIC is protected.** That account cannot be deleted, deactivated or given another role until another user is made OIC.

Smaller improvements made along the way:

- "Last login" in User Management now shows a real date. It previously always said "Never".
- Editing a user, resetting a password and changing your own password are written to the audit log (`EDIT_USER`, `RESET_PASSWORD`, `CHANGE_PASSWORD`).
- The server now refuses to save a record unless the "I have checked all flagged fields" confirmation was given. Before, only the screen checked this.
